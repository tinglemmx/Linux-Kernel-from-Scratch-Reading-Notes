# 1.4.1 GCC 扩展内嵌汇编

> 基础内嵌汇编只能写汇编指令，**扩展内嵌汇编才支持C变量和汇编互通**，也是内核里最常用的形式。 完整模板：

```C
__asm__ __volatile__ (
    汇编模板字符串        // AssemblerTemplate
    :输出操作数          // OutputOperands 可选
    :输入操作数          // InputOperands 可选
    :破坏描述符(clobber) // Clobbers 可选
);
```

## 1 关键字

1. `__asm__`：声明内嵌汇编；`asm` 是别名。
2. `__volatile__`：**易变修饰符**，告诉GCC不要删除、移动或合并这段汇编；操作硬件寄存器（fs、gs）、IO端口的代码一般必须加。

## 2 汇编模板字符串 AssemblerTemplate

- 写汇编指令，多条用`\n\t`分隔，方便汇编器格式化。
- 占位符两种写法：
    - 数字索引：`%0`、`%1`、`%2`，按输出+输入顺序编号（先输出，后输入）
    - **符号命名（推荐，可读性高）**：`%[name]`，在操作数里定义`[name]"约束"(变量)`
- 汇编模板里要写真实寄存器时用**双百分号 `%%eax`**（如 `%%fs`、`%%cr0`），用来区分占位符 `%0`/`%[name]`：只要有操作数，`%` 就会被 GCC 当作占位符开头，`%eax` 会直接报错（实测：`operand number missing after %-letter`）。
    - 例外：整个 asm **没有任何操作数**时写 `%reg` 即可（实测可编译）；此时写 `%%reg` 反而会被新版 GNU as 拒绝（`bad register name`）。

## 3 输出操作数 :OutputOperands

格式：`[asmName]"约束"(C变量)`

- 约束开头一般带 **`=`**：`=r`，表示**只写**，汇编向C变量写入结果
- 常用约束：
    - `r`：通用寄存器，GCC自动分配寄存器
	- `a`：累加器：`al` / `ax` / `eax` / `rax`，具体取决于操作数类型
	- `b`：基址寄存器：`bl` / `bx` / `ebx` / `rbx`
	- `c`：计数寄存器：`cl` / `cx` / `ecx` / `rcx`
	- `d`：数据寄存器：`dl` / `dx` / `edx` / `rdx`
    - `m`：内存单元（可作输出 `"=m"`，直接写内存）
    - `i`：立即数（**只能用于输入**，`"=i"` 编译直接报 `impossible constraint`）
    - `=`：这是输出操作数。
	- `&`：输出寄存器是 early-clobber，不能与仍需要使用的输入操作数共用寄存器。

> 为什么要用 `&`？因为编译器通常允许普通输出寄存器与输入寄存器重叠。如果输出寄存器在输入全部使用完之前就被覆盖，可能破坏尚未读取的输入值。
> 
- 输出操作数**只能写，不能当作输入读**；如果既要读又要写，使用**匹配约束**，例如 `"0"(a)`：复用第0号操作数的寄存器。

示例：`: [out1]"=r"(out1)`


### 3.1 `=` 和 `&` 的区别

|约束|含义|
|---|---|
|`"=r"`|输出使用通用寄存器；通常允许与输入操作数共用寄存器|
|`"=&r"`|输出使用通用寄存器；提前写入，避免与仍需读取的输入操作数冲突|
|`"=a"`|输出使用累加器寄存器，如 `AX`、`EAX` 或 `RAX`|
|`"=&a"`|累加器输出，并声明提前写入限制|

记忆方法： `=` 说明“这是输出”；`&` 说明“这个输出寄存器不能过早地与仍需要使用的输入共享”。

补充一点：`&` 不是所有输出都必须加。如果汇编指令会先读取完所有输入，再写入输出，通常不需要它；具体应根据指令执行顺序和输入、输出约束判断。



## 4 输入操作数 :InputOperands

同样 `[asmName]"约束"(C变量)`

- 不带`=`，是**只读**，C变量的值传给汇编。
- 可以引用输出操作数的寄存器（匹配约束）：输入写 `"0"`~`"9"`，数字指向第**几个输出**操作数，如 6.1 的 `"0"(a)`；带名字也行 `: [in] "0"(x)`——和输出同一个寄存器，既能读也能写（实测可用）。


## 5 破坏描述符 :Clobbers

告诉编译器：这段汇编**会修改哪些寄存器/内存**，GCC不要把这些寄存器的值缓存。

- 例如 `:"%eax"`，说明汇编破坏 eax 寄存器。
- `memory`：通知编译器这段汇编可能读/写**任意内存**（例如通过输入指针间接访问）。GCC 会把 asm 之前缓存在寄存器里的内存值全部写回内存，asm 之后再认为所有内存值失效、重新加载。只要用了 `m` 约束、或汇编内部有访存指令，一般都要加。
- `cc`：表示内嵌汇编修改了标志寄存器（flags register），如 `add`、`sub`、`cmp` 等。

> 注意：**clobber 列表里的寄存器不能同时是某个操作数的约束寄存器**。（`"a"(a)` 输入 + `"%eax"` clobber 会冲突，编译报 `'asm' operand has impossible constraints`。）下面的例子把 eax 当临时寄存器用，输入输出都用 `r` 绕开它：
```C
int a = 1, b = 2, c;
__asm__ __volatile__(
    "mov %[a], %%eax\n\t"
    "add %[b], %%eax\n\t"
    "mov %%eax, %[c]"
    : [c] "=r"(c)
    : [a] "r"(a), [b] "r"(b)
    : "%eax"
);  // c == 3
```

## 6 极简示例对照

### 6.1 数字索引版
> 一般不用这种写法  用  **符号命名版** 写法
```C
int a = 3, b = 4;
__asm__ __volatile__(
    "add %2,%0"
    :"=r"(a)        // %0 输出
    :"0"(a),"r"(b)  // %1=a（复用 %0 的寄存器），%2=b 输入
    : "cc"          // add 会改标志位，如实声明
);  // a == 7
```

### 6.2 符号命名版（推荐，内核代码常用）
> 使用命名操作数（`%[in1]`、`%[in2]`）可读性更好，你能直接看出每条汇编指令使用的是哪个变量，不用记 `%0`、`%1`、`%2` 的编号。
```C
int out1, out2;
int in1 = 1, in2 = 2, in3 = 3;
__asm__ __volatile__(
    "add %[in2],%[in3]\n\t"   // in3 = in2 + in3 = 5
    "add %[in1],%[in2]\n\t"   // in2 = in1 + in2 = 3
    "mov %[in3],%[out2]\n\t"  // out2 = 5
    "mov %[in2],%[out1]\n\t"  // out1 = 3
    :[out1]"=&r"(out1),[out2]"=&r"(out2)
    :[in1]"r"(in1),[in2]"r"(in2),[in3]"r"(in3)
    : "cc"
);  // out1 == 3, out2 == 5
```
> 为什么这里必须加 `&`：这段汇编**中途改写了输入寄存器 in2/in3 的值**，第 3、4 条指令还要再读它们。不加 `&` 时 GCC 会把输出与输入共用寄存器（默认假设"所有输入读完才写输出"），结果取决于寄存器分配——实测 `-O0` 碰巧正确，`-O1` 及以上输出错乱。

## 7 内核经典例子

```
#include <stdio.h>

int main(void)
{
    int out1, out2;
    int in1 = 1, in2 = 2, in3 = 3;

    __asm__ __volatile__(
        "mov %[in1], %[out1]\n\t"
        "add %[in2], %[out1]\n\t"
        "mov %[in2], %[out2]\n\t"
        "add %[in3], %[out2]\n\t"
        : [out1] "=&r" (out1),
          [out2] "=&r" (out2)
        : [in1] "r" (in1),
          [in2] "r" (in2),
          [in3] "r" (in3)
        : "cc"
    );

    printf("out1 = %d, out2 = %d\n", out1, out2);
    return 0;
}
```

## 8 重点坑点总结

1. 寄存器必须写`%%reg`，不是`%reg`；
2. 编号顺序**先输出，后输入**；
3. `__volatile__`：操作硬件、寄存器、IO必须加，防止GCC优化删除；
4. 破坏列表要如实声明修改的寄存器，否则GCC寄存器分配冲突；
5. 输出默认只写，**想要读写复用寄存器，使用匹配约束**。
